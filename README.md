# קו שירים AI

מתקשרים לקו, אומרים שם של שיר, והוא מתנגן מיוטיוב.

## איך זה עובד

1. המתקשר מקליט את שם השיר.
2. ג'מיני מתמלל את ההקלטה.
3. חיפוש ביוטיוב דרך **InnerTube** — ה-API הפנימי של יוטיוב. בלי מפתח, בלי מכסה יומית, ועובד בעברית. לוקח כשנייה.
4. **yt-dlp** מזרים את האודיו ישירות ל-ffmpeg, שחותך אותו לקטעים של 15 שניות בפורמט טלפון.
5. כל קטע שמוכן עולה לשלוחה, והקטע הראשון מתחיל להתנגן תוך שניות — בזמן שהשאר עוד זורמים.

**השיר כולו לא יורד אף פעם.** מה שיושב בשלוחה בכל רגע זה הקטעים שמתנגנים עכשיו ועוד כמה קדימה, והם נמחקים אחרי ההשמעה.

## שלוש עובדות שחייבים לדעת לפני ההקמה

**ימות לא יודעת להשמיע סטרים או כתובת אינטרנט.** היא משמיעה רק קבצים שיושבים אצלה (`f-`) או טקסט בהקראה (`t-`). לכן הארכיטקטורה היא קטעים, ולא "השמעה מהאוויר". זה נבדק מול התיעוד ומול קוד שעובד.

**השרת חייב לרוץ על חיבור לא מסונן.** בדקתי מהמחשב הזה: בקשת חיפוש ליוטיוב חוזרת `418` עם דף החסימה של נטפרי. שרת שירוץ בבית לא יעבוד. בענן זה עובד.

**נטפרי לא נוגע בקו עצמו.** השרתים של ימות הם אלה שמתקשרים לשרת, והם לא מאחורי נטפרי. אין שום דבר שצריך לפתוח או לשלוח לבדיקה.

## רווחים בין קטעים

ימות חוזרת לשרת בין קבוצת קטעים לקבוצה הבאה, וזה יוצר רווח של כמה מאות מילישניות. זו מגבלה של ימות ואי אפשר לבטל אותה לגמרי, אבל אפשר להקטין את תכיפות הרווחים: `SEG_SEC × CHAIN` = כמה שניות מוזיקה רצופה יש בין רווח לרווח.

ברירת המחדל `15 × 4` = **דקה של מוזיקה רצופה בין רווח לרווח**. אם מפריע, מגדילים ל-`SEG_SEC=20` ו-`CHAIN=6` (שתי דקות). הקשה על מקש עוצרת מיד בכל מקרה, כי ימות קוטעת את ההשמעה, ולכן שרשרת ארוכה לא פוגעת בזמן התגובה.

# הקמה

## שלב 1: שלוחות בימות

> ⚠️ קודם קוראים את [בטיחות-ובידוד.md](בטיחות-ובידוד.md) — שם כתוב בדיוק מה נוצר ובמה לא נוגעים.

**נבדק במערכת `0779709383` ב-17.11.2026:** כל השלוחות 0–9 קיימות ו**ריקות לגמרי**. שלוחות 5 ו-9 כבר מסוג `api` אבל מצביעות על `your-service-name.onrender.com` — כלומר ההקמה של קו ה-AI הישן התחילה ולא הושלמה.

לכן נשתמש ב-**7** ו-**8**, ונשאיר את 1, 5 ו-9 פנויות לפרויקט הישן:

| שלוחה | תפקיד | מצב כרגע |
|---|---|---|
| **8** | קבצים — הקלטות וקטעי השיר | ריקה ✅ (אומת מול ה-API) |
| **7** | ה-API של הקו | ריקה, צריך לשנות ל-`type=api` |

שלוחה 8 כבר קיימת וריקה, אז אין מה ליצור. נכנסים ל[ימות](https://www.call2all.co.il/ym/), **"מערכת תוכן"**, שלוחה **7**, לשונית **"הגדרות מתקדמות"**, בתפריט בוחרים **`ext.ini`**, מוחקים ומדביקים (את הכתובת נשלים בשלב 4):

```
type=api
api_link=http://<כתובת-השרת>/yemot
```

> סוג API בתפריט של ימות לא תמיד עובד, ולכן מחברים דרך קובץ ההגדרות. כך זה עובד תמיד.

## שלב 3: פריסה ב-Render (בלי כרטיס אשראי)

**למה Render ולא גוגל קלאוד:** אישרתי שגוגל דורשת חשבון חיוב עם כרטיס אשראי **גם למכונה "החינמית לתמיד"**, וכך גם Oracle ו-Fly.io. גם Docker ב-Hugging Face עבר לתוכנית בתשלום. Render היא האפשרות היחידה שנשארה שמריצה Docker בלי כרטיס.

נרשמים ב-[Render](https://dashboard.render.com/register) (אפשר עם חשבון GitHub), ואז **New → Blueprint**, בוחרים את הריפו `kav-shirim`. Render קורא את `render.yaml` ובונה לבד.

אחר כך, ב-**Environment** של השירות, מוסיפים את שני הסודות:

| המשתנה | הערך |
|---|---|
| `YEMOT_TOKEN` | `0779709383:הסיסמה` |
| `GEMINI_API_KEYS` | המפתח מ-AI Studio (או שניים, מופרדים בפסיק) |

הבנייה הראשונה לוקחת 5 עד 10 דקות. בסוף מקבלים כתובת כמו `https://kav-shirim.onrender.com`.

### ⚠️ שתי המגבלות של התוכנית החינמית

**1. השירות נרדם אחרי 15 דקות בלי תנועה**, והתעוררות לוקחת כדקה — כלומר השיחה הראשונה אחרי הפסקה תיפול. הפתרון: מעיר חיצוני. נרשמים ב-[cron-job.org](https://console.cron-job.org/) (חינם, בלי כרטיס, נבדק שפתוח בנטפרי) ויוצרים משימה שפונה ל-`https://<השם שלך>.onrender.com/` **כל 10 דקות**. המכסה החינמית היא 750 שעות בחודש, שזה בדיוק חודש שלם של שירות אחד.

**2. 512MB זיכרון ו-0.1 CPU.** זה חלש, וייתכן שספק ה-PO Token ייהרג בזיכרון או שההכנה תהיה איטית. **זה לא ידוע מראש** — בדיקת `/selftest` מחזירה גם דוח זיכרון, ו-`/trystream` יגיד תוך דקה אם החילוץ באמת עובד. אם זה לא מחזיק, אותה תמונת Docker עוברת לכל מקום אחר בלי שינוי קוד.

> **אם בהמשך תסכים לכרטיס:** ב-GCP יש `e2-micro` חינמית לתמיד עם מכונה אמיתית. הקובץ [startup-script.sh](startup-script.sh) מוכן לזה — מדביקים אותו בשדה Startup script בטופס יצירת המכונה. **אל תנסה SSH בדפדפן או Cloud Shell: שניהם חסומים בנטפרי (418).**

## שלב 4: בדיקה לפני שמתקשרים

פותחים בדפדפן (מחליפים בכתובת שקיבלת):

**`<הכתובת>/selftest`** — בודק את כל החיבורים. צריך לקבל `"ok": true` ושש בדיקות ירוקות:

| הבדיקה | מה היא אומרת |
|---|---|
| `yemot_token` | הטוקן נכון ושלוחת הקבצים קיימת |
| `ext_contents` | **בטיחות:** מזהיר אם בשלוחה יש קבצים שאינם של הקו |
| `gemini` | המפתח הוגדר |
| `youtube_search` | יוטיוב נגיש מהשרת |
| `pot_provider` | ספק ה-PO Token מאזין — **בלעדיו יוטיוב יחסום** |
| `ytdlp` / `ffmpeg` | הכלים מותקנים |
| `resources` | כמה זיכרון יש ונשאר — חשוב ב-512MB |

**`<הכתובת>/trystream?q=אדון עולם`** — הבדיקה האמיתית: מחפש, מחלץ ומקודד 12 שניות. צריך לקבל `"ok": true` ו-`wavBytes` של כ-190,000. אם זה עובד, הקו יעבוד.

## שלב 6: מחברים ומתקשרים

## הגדרות

כולן אופציונליות חוץ משתי הראשונות. מוסיפים אותן ל-`docker run` בתור `-e NAME=value`.

| משתנה | ברירת מחדל | הסבר |
|---|---|---|
| `YEMOT_TOKEN` | — | **חובה.** מספר מערכת:סיסמה |
| `GEMINI_API_KEYS` | — | **חובה.** מפתח או כמה מופרדים בפסיק |
| `EXT_PATH` | `1` | שלוחת הקבצים (אצלך: `8`) |
| `GREETING` | "שלום. אמור את שם השיר..." | הפתיח |
| `REC_MAX` | `10` | שניות מקסימום להקלטת שם השיר |
| `SEG_SEC` | `15` | אורך קטע בשניות |
| `CHAIN` | `4` | כמה קטעים בכל סבב |
| `SONG_MAX_MIN` | `10` | מקסימום דקות לשיר |
| `LOOKAHEAD` | `8` | כמה קטעים מעלים מראש |
| `STT_MODEL` | `gemini-3.5-flash` | מודל התמלול |

## כשמשהו לא עובד

**לוג חי:** `sudo docker logs -f kav`

| מה רואים | הסיבה |
|---|---|
| `Sign in to confirm you're not a bot` | ספק ה-PO Token לא עלה. לבדוק `/selftest`, ואם `pot_provider` אדום: `sudo docker restart kav` |
| `יוטיוב חסום מהשרת הזה (418)` | השרת מאחורי מסנן. הוא חייב לרוץ בענן |
| `העלאה נכשלה` | הטוקן של ימות שגוי, או ששלוחה 1 לא קיימת |
| המכולה נהרגת | חסר זיכרון. לוודא ש-`swapon --show` מראה 2GB |
| מוזיקה מקוטעת | להגדיל `SEG_SEC` ו-`CHAIN` |

**עדכון הקוד אחרי שינוי:**

```bash
cd /opt/kav && sudo git pull && sudo docker build -t kav-shirim . && sudo docker restart kav
```
